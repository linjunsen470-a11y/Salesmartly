# SaleSmartly Pro 本地聊天归档

Chrome 扩展 + Windows 本地助手。复用已登录的 Chrome Profile，保存网页可取得的聊天消息及媒体，不依赖 Max、OpenAPI、Webhook 或服务器。

当前 v0.3.0 默认采集左侧“全部”视图的会话，启动时核对全部接待成员。日期模式先按实际最后消息时间筛选客户，再逐个加载聊天；已确认消息时间倒序后，普通列表达到起始日期即停止发现更早的客户。客户原名、备注名、手机号和自有社媒账号分别保存，并可导出客户 CSV 及带资料的离线聊天。47 项测试通过，包含日期截止、旧置顶会话、客户资料更新、250 位客户控制器流程、虚拟列表定位及恢复去重。本机实测限定 2026-09-27 起的 5 位客户，完成导出 229 条消息、21 项媒体，未验证整个账号的全量范围。改动与真实验收见 [v0.3 说明](docs/V03_SCOPE.md)。[v0.2.1 记录](docs/V021_FIX.md)保留为历史证据，其“我的”任务不代表本次“全部”任务。

## 使用

1. 在已登录 SaleSmartly 的 Chrome Profile 中重新加载本扩展；目录为 `D:\work\Salesmartly\dist\extension`。
2. 刷新 `https://app.salesmartly.com/next/chat`，点击“SaleSmartly 本地归档”图标。面板自动连接本地程序。
3. 选择归档面板的历史起始日期，例如 `2026-08-01`；保存北京时间该日零点至任务启动时的消息。
4. 点击“开始采集全部会话”。程序自动切换左侧“全部”和全部会话状态，核对成员筛选，再打开同 Profile 的独立采集标签页。请保持采集页可见；原聊天页可放到另一窗口使用。切换到后台会暂停，点击继续会自动切回采集页。打开客户可能触发平台已读。
5. 面板显示本次视图、日期内候选、已处理和待处理客户，以及当前客户资料和消息写入数量。可暂停、继续或结束任务。刷新、关闭采集页、重启或较长中断会保留断点，并要求继续。

“更多选项”可导出本次客户清单 CSV、每位客户的离线 HTML，或选择最近 N 条/全部可访问历史、客户数上限及重试媒体。离线 HTML 按本次任务的客户和时间范围过滤，旧库里的更早消息不会混进本次副本。部分完成的任务可点击“重试未完成部分”，跳过已完成客户。消息每页提交后即在本地归档，不必等整个客户列表遍历完毕。当前保留小范围验收设置：2026-09-27、最多 5 位；更早的大任务已暂停。

默认“全部”包含当前登录权限允许访问的各成员客户。启动前核对搜索、社媒账号和接待成员筛选；存在搜索词或接待成员限制会明确提示，避免误称全量。临时筛选在新页丢失、只选择部分具体社媒账号或详情不一致时也会暂停。旧“我的”任务保留为旧任务，可新建“全部”采集；不会删除旧档案。

最后消息早于起始日期的客户不进入日期任务，置顶旧客户也排除。置顶行不用于判断列表日期截止；日期未知或顺序无法确认时继续核对，不假装已经到达截止。每个选中的客户仍须向上加载至起始日期或网页明确的历史末尾。

## 保存与去重

归档目录：`D:\work\Salesmartly\.local\archive`。

- `archive.sqlite`：消息、内容版本、客户原名/备注/手机号/自有社媒账号、下载状态、任务及已证明的覆盖区间。
- `media/`：本地媒体，以附件与任务 ID 命名；旧文件仍可使用。
- `analysis_messages` / `analysis_attachments` / `analysis_customers`：供未来只读分析的 SQLite 视图。
- `exports/`：客户 CSV；聊天导出包含 HTML、`customer.json`、JSONL、媒体副本及缺失清单。

同一项目、客户、平台消息 ID 对应同一条消息；会话或渠道信息变化不另建消息。正文或实际媒体变化才新增内容版本；已读、发送方向校正等更新现有记录。具有来源更新时间的迟到旧响应不会覆盖新内容。缺少来源版本时只能依据最新观察，无法恢复网页未返回的修改或删除。

重复任务在已有连续覆盖的基础上回看最近 7 天，并至少重看 50 条已归档消息。手动样本、范围更早或未证明覆盖的客户仍正常向前加载，不在遇到旧 ID 时直接结束。

媒体自动下载，最多并发 2 项。只检查浏览器完成状态、文件存在且非空，并读取少量文件头防止登录页误入库；不做 SHA-256 扫描或全文件解码。短期签名刷新尽量复用现有文件，真实资源替换重新下载。仅清理已成功导入的本任务暂存文件。

## 覆盖限制

只归档当前登录权限下网页可访问的数据。日期、数量和服务器明确的分页结束信号用于结束加载；空白视窗、超时和解析失败都不表示完整。未确认的客户和列表范围记为部分完成，媒体失败单独显示。系统操作记录不用于计算聊天条数或历史日期边界。

Blob、HLS/DASH 分片、已失效的原文件、只有缩略图的资源和未适配的实时消息可能无法取得。当前主线是历史归档；全天候监听及 AI 回复尚未实现。

原始响应和媒体 URL 留在本地；不保存 Cookie、Authorization 或完整请求头，不向模型发送客户数据。响应最多 16 MB，待确认队列与单批重组最多 8 MB；超过上限明确暂停，保留已提交内容。

## 开发与验证

```powershell
cd D:\work\Salesmartly
npm run build
npm run check
npm test
node tools/smoke-native.ts
node tools/verify-v02.ts
# 查看当前真实归档摘要，不输出聊天正文
node tools/live-v02-summary.ts
# 复核最新“全部”日期任务、旧日期排除、客户资料、重复记录及媒体存在性
node tools/verify-v03-live.ts
# 从命令行导出最新任务的客户清单
node apps/native-host/cli.ts export-customers
# 复核本次保存的真实验收证据及媒体存在性
node tools/verify-v02-live.ts
# 可选：独立测试库中的 100,000 条消息及重复采集
node tools/verify-v02.ts --scale
```

需要 Node.js 24、Chrome 120+。本机助手已注册到当前 Windows 用户。移动项目目录后重新构建并运行 `npm run setup:register`。保留 `.local/extension-public-key.json` 可维持现有扩展 ID。

已安装 v0.2.1 后，构建完成可在网页面板点击“更多选项 → 应用本地更新”；任务会保留并暂停。更新后可以继续同一任务，或新建“全部”任务。首次安装或仍使用旧版时才需要在 Chrome 扩展管理页手动加载。
