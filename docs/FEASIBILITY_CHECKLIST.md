# P0：Pro 浏览器采集可行性与验收

更新日期：2026-09-30。用户维持 Pro；本清单不需要 Max、OpenAPI 或 API Token。状态：两个真实会话的手动采集及离线样本包已通过初步验证，84 条消息、6 个媒体、0 项已识别媒体缺失。全部历史、全部客户及文件附件仍未验收。详细证据见 [实现与验证记录](IMPLEMENTATION_STATUS.md)。

## 1. 样本范围

- [ ] 确认项目、Messenger 主页/渠道账号、WhatsApp 的具体接入模式。
- [ ] 每个实际接入模式选择 3–5 个会话，含近期、较早、长历史与已结束会话。
- [ ] 覆盖收发双方、重复文本、引用、贴纸与可观察的修改/撤回；无样本记录“无样本”。
- [ ] 各准备至少一张原图、一条完整语音、一段完整视频和一个文件；纳入较旧媒体。
- [ ] 有群聊时加入群成员/发送人样本，不同渠道同名客户单独标注。
- [ ] 手工记录最早已知消息与预期附件数，作为采集对照。
- [ ] 记录客户数量、最长历史跨度和大媒体情况，不用单屏 DOM 数量估算总量。

## 2. 标签页与采集器

- [ ] 扩展仅连接选定 SaleSmartly 标签页，识别当前项目/渠道/客户。
- [ ] 先开始观察，再打开样本会话并触发历史加载，确认监听时机。
- [ ] 识别历史 JSON、实时事件和媒体请求，确认是否使用 WebSocket/worker/iframe。
- [ ] 只保存聊天相关响应；原始授权头、Cookie、登录响应和其他标签页不进入日志。
- [ ] 确认稳定消息 ID、客户/会话 ID、发送人、时间、类型和引用格式。
- [ ] 区分客户完整历史与一次会话的响应范围。
- [ ] 取得响应正文；缓存命中/正文不可取时能报告并通过正常页面加载复查。
- [ ] 开同页 DevTools、关闭标签页、取消附着后任务暂停并记录原因。
- [x] Native Messaging host 连接正确；本地提交后才确认接收，重复发送不重复入库。

已确认：用户指定 Profile、选定聊天标签页、真实 `mid`、项目/客户/会话 ID、时间、`sender_type` 与 `content.msg` 媒体地址。渠道账号字段尚缺，标记 `unknown`；Fetch/XHR 响应取得成功，实时 WebSocket/worker 未验收。

## 3. 历史加载与会话枚举

- [ ] 定位实际聊天滚动容器，连续加载至少三批历史；旧节点移出 DOM 后数据仍在本地。
- [ ] 观察分页/游标/时间/序列参数与终止信息，不假定使用开放 API 机制。
- [ ] 重叠页、同一时间多条消息、重复文本均能保持正确消息集合。
- [ ] 较早已知消息可取；到顶提示或后端终止证据能记录。
- [ ] 加载失败、慢响应、连续无 DOM 变化和解析失败不会被判定“已全部完成”。
- [ ] 客户/会话列表的多个状态、渠道筛选和已结束入口可枚举。
- [ ] 列表顺序变化时按稳定 ID 去重并复查，存在枚举边界时明确记录。
- [ ] 切换会话后迟到响应归属正确，不把旧会话或其他客户实时事件归到当前客户。
- [ ] 打开会话对已读/读回执有无影响完成验证；说明采集标签页的前台/可见条件。

## 4. 原媒体获取

- [ ] 图片：区分原图、缩略图、压缩预览，记录实际取得的版本和分辨率。
- [ ] 语音：原文件完整保存，断网后可播放或用本地播放器打开，时长匹配。
- [ ] 视频：原文件或经验证的完整媒体保存；仅收到 Range/206 片段不算完成。
- [ ] 文件：大小、格式、原文件名与内容正确，排除 HTML 登录页和错误页。
- [ ] 附件与消息 ID 稳定对应，多附件、同文件重复出现、预览资源分别处理。
- [ ] Cookie/签名等授权条件明确，普通本地下载失败时有已验证的浏览器下载路径。
- [ ] chrome.downloads 完成后能按 downloadId 导入暂存文件，目录包含中文/空格时正常。
- [ ] 没有可用下载按钮的资源有可执行的读取路径；普通 Blob 与 MediaSource 区分。
- [ ] 有 HLS/DASH/分片时单独验证；没有样本时标未验证，不默认声称支持。
- [ ] URL 失效后重新打开同一消息能否刷新已验证；无法刷新时保留缺失原因。
- [ ] 大文件不整体驻留扩展内存，下载中断与磁盘不足不会损坏既有档案。

## 6. 可靠性与导出

## 7. P0 结果与下一步

| 实测结果 | 下一阶段 |
| --- | --- |
| 消息结构稳定，原媒体可保存，历史加载可复核 | 实现 P1 单客户自动历史采集 |
| 常见媒体可取，但某些只得到预览/分片/Blob | 明确类型边界，为这些样本增加专用处理后再声称支持 |
| 消息可归档，但媒体无法完整取得 | 单列缺口与原因，保持重试入口，不算完整媒体归档 |
| 单客户可行，但全部客户枚举不足 | 先支持当前/已选客户导出，记录未覆盖列表，继续验证批量范围 |
| 网页本身没有较早数据或原资源已失效 | 报告最早可得日期与缺失素材，不能承诺恢复 |
| 页面结构改变或身份无法确认 | 暂停相关任务，修复解析器/定位器并重新对照样本 |

P0 必须交付可离线打开的样本包、能力矩阵、历史加载证据、缺失原因和下一阶段范围。保存媒体 URL、截图或单屏 DOM 文本均不等于完成。

本轮已交付 HTML、JSONL、版本、媒体、manifest 和缺失 CSV；校验数量、大小、SHA-256 与相对链接通过，单独导出目录在 Chrome 预览通过。样本的已识别媒体保存率为 6/6，此结论只覆盖已测记录。较早历史由人工滚动触发，最早边界尚无可靠证据；未验证的勾选项保留未完成。下一阶段先实现单客户受控历史加载与分页边界，再做全客户枚举。
