# v0.3.0：全部成员、日期截止与客户资料

这次修复针对实际使用中确认的三处差距：旧任务沿用“我的”，日期只限制消息而未限制客户队列，客户资料未随离线档案保存。旧版局部验收不能证明左侧“全部”的完整功能。

## 最终行为

- 新任务自动选择左侧“全部”，同时选择全部会话状态，读取详细成员和账号筛选。接待成员限制、搜索条件或新页范围不一致会明确提示，避免把局部结果当成全部。当前登录账号的可见权限仍是访问边界。
- 日期模式取网页列表的 `snippet_time`，它表示最后一条消息，无论由客户还是成员发送。`last_reply_time` 仅代表成员回复，不能单独替代最后消息时间；创建日期也不使用。列表没有该字段时才取双方最后回复时间的较新值。
- 最后消息早于起始日期的客户在进入待采集队列前排除，本地助手再次检查。以 `2026-08-01` 为例，最后消息在 `2026-06-13` 的客户不会再被打开采集。
- 启动时在网页列表设置确认“按消息时间倒序排序”。置顶行可不按日期排列，因此旧置顶客户只排除、不触发截止；普通行已确认按时间倒序且达到起始日期后，停止请求后面的客户列表。晚到的早先列表响应不会重新打开已确认的截止。
- 每批符合日期的客户立即逐个采集。每个会话仍须向上加载至所选日期或网页明确的历史末尾；超时和未知响应记为缺口。日期是北京时间零点至任务启动时，之后的新消息留给下次任务。
- 保存客户原名 `name`、业务备注 `remark_name`、手机号 `phone`、渠道代码及自有社媒账号 `channel_name`。空字段不覆盖已知联系方式；同一项目和客户更新原行。联系人信息与账号信息分开，避免把自有 Messenger 主页误当客户名字。
- 更多选项新增本次客户 CSV；离线 HTML 页头、`customer.json` 和 `manifest.json` 同时包含客户资料。导出的客户和消息按本次任务及时间范围过滤；旧库中的更早历史保留，但不混入新副本。起止时间比较兼容秒和毫秒精度。网页不提供的号码显示“未取得”。CSV 用 UTF-8 BOM，号码保留完整数字，Excel 中以文本防止丢精度。
- 客户定位排除虚拟列表移出视口的回收行，使用整张客户卡片点击并核对当前会话；目标已在上方时先回到列表顶部。面板区分本次消息观察次数、新增/更新/重复和整个档案库的媒体总数。
- 旧“我的”任务显示“旧任务”，新建“全部”采集会保留旧库和原消息。已完成客户在恢复时跳过，未完成客户重新观察后按消息 ID 去重。媒体仍采用文件存在、非空与格式检查，没有 SHA-256 扫描。

## 验证

47 项测试通过，新增用例验证左侧“全部”与上方状态“全部”的区别、无法核对成员筛选时停止、最后消息晚于成员最后回复、置顶旧会话排除、日期与时区边界、未知日期/未确认排序不会误停止、联系方式更新去重和 HTML/CSV 输出。完整控制器测试覆盖 250 位客户、队列恢复及异步分页。补充回归验证晚到的早先列表响应不会清除日期截止、虚拟列表回收行不被点击，以及旧库消息按新任务日期导出。TypeScript 检查和 Native Messaging 独立测试库验收通过。

## 使用

本机已通过网页“应用本地更新”加载 v0.3.0，不需要重新安装或增加权限。日常选择起始日期后点击“开始采集全部会话”，保持专用页可见。暂停后点击“继续”；已结束且有缺口可点击“重试未完成部分”。更多选项提供客户 CSV 和单客户离线 HTML；导出路径显示在面板中。

复核最新实际结果：

```powershell
node tools/verify-v03-live.ts
node apps/native-host/cli.ts export-customers 974b272e-0001-4295-b746-b18e884056b9
node apps/native-host/cli.ts export <会话ID> 974b272e-0001-4295-b746-b18e884056b9
node tools/verify-export.ts <离线目录/index.html>
```

网页权限、未返回的联系方式、已失效媒体和服务器限制无法由插件补齐。日期未知或排序无法确认不会宣称完整；缺口会明确显示并可重试。
