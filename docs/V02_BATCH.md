# v0.2 批量与增量归档

此文记录 v0.2 当时的实现与小范围验收。随后用户的大批量任务暴露了两处问题：先枚举完整客户列表才采集消息，以及姓名点击取得预取数据但未切换当前会话。不限客户数的真实流程未被当时的两位客户验收覆盖；修复见 [v0.2.1](V021_FIX.md)。

2026-09-30。用户批准继续开发，并要求取消过度工程化设计。保留 TypeScript、Chrome MV3、Native Messaging、SQLite，没有添加 Electron、服务端、模型调用或新权限。

## 已实现

- 原页确定视图、状态、搜索和筛选详情；同 Profile 创建可见的独立采集页，核对范围后才归档。SaleSmartly 虚拟列表依赖页面渲染，Chrome 后台标签会暂停部分渲染，因此后台时暂停，继续时自动切回采集页。原聊天页可放到另一个窗口。
- 观察网页真实客户列表响应，滚动虚拟列表并建立去重客户队列；枚举完成后冻结队列，新增客户留给下一次任务。客户上限可控制小范围验收。
- 顺序打开客户，以实际会话列表 ID 优先定位，收到结构化客户 ID 后确认归属。逐页向上加载，所有批次收到 SQLite 提交 ACK 后才更新控制器进度。
- 日期模式使用 UTC+8 起始日和任务启动时冻结的结束时间；也支持至少 N 条或全部可访问历史。系统操作记录不参与聊天边界与条数计算。
- 平台明确的分页结束、指定日期或足够独立消息决定停止。超时、布局变化、同名无法定位、空响应不匹配等记为缺口，不作为完整历史。
- 已证明覆盖的日期范围可以启用增量回看：最近 7 天与至少 50 条旧消息，两者都满足。较早日期、手动样本与缺口客户继续完整回填。
- 任务和客户状态保存到 SQLite。暂停、结束、关闭采集页、浏览器/扩展重启、长时间中断后保留已归档内容；继续时重新打开和加载当前客户，通过平台 ID 去重。断点粒度是客户，不依赖易失效的网页分页 token。
- 主表按项目、客户、消息 ID 复用现有记录及旧 ID。正文/媒体变化增加内容版本；方向校正和读状态变化只更新当前记录。来源更新时间较旧或同版本冲突时保留较新正文。
- 同一附件的下载状态和路径复用；签名参数刷新不必重新下载，真实资源变更清空当前关联并下载新文件，旧下载不能覆盖新附件。旧媒体文件保留。
- 媒体自动下载，最多并发 2 项。无整文件 SHA-256、无内容寻址仓库、无完整解码扫描。只做完成状态、文件存在/非空、少量文件头识别和已注册暂存路径检查。
- 成功导入后仅清理该已注册暂存文件；新旧媒体文件名均能导出。批量结束不自动复制 HTML；默认用 SQLite + 媒体索引，保留可选离线 HTML。
- 网页面板简化为日期、开始、暂停/继续/结束及进度。首页显示下一次的采集范围，非日期模式隐藏日期输入，非条数模式隐藏 N 输入；修改设置即记住。自动连接和刷新，诊断与手动操作收进“更多选项”，客户下拉显示名称和渠道。
- 增加 `analysis_messages` 与 `analysis_attachments` 视图供后续只读分析；没有发送客户数据给大模型。

## 实际限制

- 暂时不自动复制任意临时筛选；采集页与原页详情不同即暂停。建议使用平台已保存的视图。仅勾选部分具体社媒账号的筛选详情仍未适配，会明确拒绝开始；全部账号及整个渠道的条件可核对。
- 采集页需保持可见，不能把后台标签的虚拟列表当成可靠的无人值守采集。Chrome 休眠、最小化和用户操作会导致暂停或缺口；恢复从当前客户重载并去重。
- 枚举结果属于当前视图和条件，不包含当前网页未暴露的其他项目/客户。列表结束未确认时，任务保留“部分范围未确认”。
- 本轮验证了现有两位 WhatsApp 客户的条数与日期停止条件，尚未证明各渠道的全部历史结束字段。真实历史响应包含 `next_pk`、`package_limit`，没有已适配的明确结束标志，因此“全部历史”可能在已有消息后记为部分完成。未知字段不会据空页面推断结束；每批保留少量分页元数据供后续样本适配。
- 来源更新时间缺失时，无法确定两份不同内容谁更新；未观察到的撤回、删除、修改无法自动恢复。已观察撤回软标记并保留文件，不依据“列表中少了一条”删除本地记录。
- Blob、分片视频、原链接失效、平台未同步或仅提供缩略图的内容仍需后续样本适配。文件不存在、格式不认识、无地址和下载失败保留原因。
- 客户列表在任务中重排、过滤条件改变或登录过期可能导致客户无法选择；保存该客户的缺口并处理其余可选客户。身份、范围、解析或本地写入错误会暂停整个任务。
